# Working in this repo

## Where config lives

This repo is the chezmoi source for everything it manages. Read and edit
config here, not the live copies in `$HOME`: those are generated by
`chezmoi apply` and get overwritten. `README.md` has the full overview.

| Tool | Source in this repo | Applied to |
|---|---|---|
| zsh | `dot_zshrc`, `dot_zshenv`, `dot_zprofile` | `~/.zshrc` etc. |
| git | `dot_gitconfig`, `dot_gitignore` | `~/.gitconfig`, `~/.gitignore` |
| tmux | `dot_tmux.conf` | `~/.tmux.conf` |
| Ghostty | `dot_config/ghostty/config.ghostty` | `~/.config/ghostty/` |
| Hammerspoon | `dot_hammerspoon/init.lua` | `~/.hammerspoon/` |
| Homebrew packages | `dot_Brewfile` | `~/.Brewfile` |
| mise (node, python, terraform) | `dot_config/mise/config.toml` | `~/.config/mise/` |
| Global npm packages | `dot_default-npm-packages` | `~/.default-npm-packages` |
| topgrade | `dot_config/topgrade.toml` | `~/.config/topgrade.toml` |
| Doom Emacs (incl. agent-shell) | `dot_doom.d/` | `~/.doom.d/` |
| Colima | `dot_colima/_templates/default.yaml` | `~/.colima/` |
| Docker CLI | `dot_docker/modify_private_config.json` | patches `~/.docker/config.json` |
| chezmoi | `.chezmoi.toml.tmpl` | `~/.config/chezmoi/` |

The `run_*` scripts run install and sync steps during `chezmoi apply`.

Not managed here: Doom itself (`~/.emacs.d`), installed Emacs packages
(`~/.emacs.d/.local/straight/repos/`), and machine-local overrides like
`~/.zshrc.local`. Only look in those when this repo can't answer the question,
for example when debugging how a package itself behaves.

## Applying changes

`chezmoi apply` is safe to run from anywhere, including agent-shell or a
Claude Code session. Its run scripts are written to be environment-independent.

## Never run a bare `doom sync`

Doom's `doom sync` snapshots the calling process's environment into Emacs's
envvar file. Run from inside an agent session, that file picks up the
session's `CLAUDE*` variables, and the next Claude started in agent-shell
believes it is a nested session.

Let `chezmoi apply` handle it (the doom-sync run script runs it from a
scrubbed login shell). If a resync is needed without a Doom config change,
for example after a shell PATH change, tell the user to run `doom sync` from
their own terminal rather than running it yourself.
